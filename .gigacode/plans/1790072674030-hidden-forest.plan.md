## Этап 2: Исправление существующих тестов

### 2.1 Исправить KeyHint usage (pointer vs value)
**Файлы:** test_container_info.cxx, test_container_creation.cxx
**Проблема:** Методы принимают `const KeyHint*`, тесты передают `KeyHint` по значению
**Решение:** Заменить `hint` на `&hint` во всех вызовах

### 2.2 Привести все тесты к Java-подходу
**Подход Java:**
1. Создать контейнер через `createXxx(key, hint, initialData)` → получить `KeyHint`
2. Использовать `streamXxx(key)` для верификации содержимого
3. Выполнять operation → проверять результат
4. Верифицировать состояние через `streamXxx`
5. Тестировать error paths (NOT_FOUND для несуществующих ключей)
6. Тестировать locks (READ/WRITE/GLOBAL + owner/intruder)
7. Тестировать TTL (set/get + expiry)

**Файлы для переписывания:**

## Этап 5: Memory Management

### Правила:
1. **ValuePtr, KeyPtr, OrderedValuePtr** — использовать `std::shared_ptr` (уже есть в types.hxx)
2. **test_base::make_value/key** — возвращают smart pointers, не нужно освобождать вручную
3. **std::vector<ValuePtr>** — при удалении vector smart pointers автоматически освобождаются
4. **KeyHint** — plain struct, аллоцируется на стеке, не требует очистки
5. **Избегать raw pointers** — все данные через smart pointers
6. **Не хранить указатели на временные объекты** — все временные объекты должны жить до конца теста

### Проверка:
- Использовать `valgrind --leak-check=full` после запуска тестов
- Проверить, что нет double-free при копировании vector<ValuePtr>
